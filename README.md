# 구해줘 빈집 — 수정본 v4

첨부한 최신 GitHub 파일 묶음을 기준으로 수정한 Streamlit 프로그램이다.

## GitHub에 적용하기

1. 다운로드한 수정본 ZIP을 압축 해제한다.
2. 압축 해제한 폴더 **안의 내용**을 기존 저장소의 app.py가 있던 위치에 넣는다. 상위 폴더를 통째로 한 단계 더 만들지 않는다.
3. 아래 파일을 교체하거나 추가한다. 특히 assets 폴더와 .streamlit/config.toml도 필요하다.

```
app.py
model.py
report_model.py
report_io.py
table_io.py
upload_tools.py
visuals.py
requirements.txt
assets/                    로고와 시설 아이콘 17개
.streamlit/config.toml     색상 설정
.gitignore
README.md
test_report.py
test_upload_tools.py
```

4. 로컬 Git 저장소를 사용한다면 위 변경을 커밋하고 push한다. GitHub 웹에서 올릴 경우 파일과 폴더 구조를 유지하여 업로드하고 Commit changes로 저장한다. `.streamlit/config.toml`이 누락되면 GitHub의 Add file → Create new file에서 해당 경로로 만들고 이 묶음의 내용을 복사한다.
5. 연결된 Streamlit 앱에서 변경 반영을 확인한다. 배경 색이 이전 값이면 앱을 재시작하고 브라우저를 새로고침한다. Streamlit의 실행 파일 경로는 계속 app.py다.

실제 GitHub 저장소와 배포 사이트에는 아직 이 수정본을 반영하지 않았다.

## 기존 저장소 정리

이번 첨부본 기준으로 `.venv/`, `__pycache__/`, `app_backup_v2.py`, `admin_sales.py`, `admin_sales_ui.py`는 이 프로그램 실행에 필요하지 않다. 실제 빈집 Excel 파일 두 개와 기존 examples 폴더도 app.py에서 자동으로 읽지 않으므로 보관 목적이 없다면 제거할 수 있다. 위 목록의 실행 파일과 assets, .streamlit은 유지한다.

`.gitignore`는 앞으로 추가되는 환경·캐시 파일을 제외한다. 이미 GitHub에 올라간 .venv를 자동 삭제하지 않는다. 삭제 전 필요한 원본은 별도로 내려받아 보관한다.

## 데이터 업로드

- **ZIP으로 한번에**: 데이터 CSV·XLSX만 ZIP으로 묶어 올린다. 프로그램 ZIP과 데이터 ZIP은 서로 다르다. ZIP 안의 하위 폴더도 읽는다.
- 파일명 키워드로 각 입력칸에 파일이 미리 선택된다. 자동 연결 결과를 확인하고 드롭다운으로 변경한다. 해당 입력칸의 추가·교체 파일은 드롭다운 선택보다 우선한다.
- 공통 목록에 데이터 추가에서 CSV·XLSX를 더 올릴 수도 있다.
- **각각 업로드**: 시설별 입력칸에 CSV·XLSX를 직접 올린다.
- 위도·경도·시설명은 요청한 키워드가 포함된 첫 번째 열을 자동 선택한다. 잘못 연결되면 직접 변경한다. 시설명은 선택 항목이다.
- 빈집 자료는 ID·위도·경도·행정동을 각각 선택해야 한다. 행정동은 코드 또는 명칭으로 통계와 연결하며, 주소에서 행정동을 추정하지 않는다.
- ZIP 내부 데이터는 메모리에서 처리하며 원본 데이터 파일을 프로그램 폴더에 저장하지 않는다.

ZIP 제한은 내부 항목 1,000개, 데이터 파일당 압축 해제 크기 100MB, 총 압축 해제 크기 300MB다. CSV 인코딩 자동 처리는 기존 table_io.py를 사용한다.

## 경찰·편의시설 통합 입력

경찰시설은 통합 파일 한 개 또는 경찰서와 지구대·파출소 파일 두 개를 선택할 수 있다. 별도 파일은 좌표를 기준으로 합친다.

편의시설은 편의점·마트·약국 파일을 각각 넣거나 통합 파일을 넣을 수 있다. 통합 파일에는 위도·경도 외에 시설 종류 열이 있어야 한다. 예를 들어 종류 열에 '편의점', '마트', '약국'을 넣고 각 값을 화면에서 해당 종류로 연결한다. 세 종류를 모두 조사한 자료인지 확인한 뒤 계산한다. 통합 자료에 없는 종류를 누락으로 볼지 실제 0개로 볼지 사용자가 확인하도록 했다.

같은 시설 ID여도 좌표가 다르면 보존한다. 시설 종류가 있는 경우 종류도 중복 판단에 포함한다. 서로 다른 위치를 이전 경고문 때문에 삭제하지 않는다.

## 지도 표시

순위 배지는 A:1위, B:2위처럼 표시한다. 점을 선택하거나 ID 선택 후 주변 근거시설 보기 버튼을 누르면 해당 빈집의 상세 지도에 근거시설이 나타난다.

| 그룹 | 색상 | 시설 |
|---|---|---|
| 교통 | #01A8AF | 버스정류장·지하철역·공영주차장 |
| 생활편의 | #58B368 | 편의점·마트·약국 |
| 안전 | #E65373 | CCTV·경찰서/지구대/파출소·소방서 |
| 대학·학습·체육 | #8A63D2 | 도서관·운동시설·대학교 |
| 산업·보육·교육 | #D89B24 | 산업단지·어린이집,유치원·초등학교 |
| 관광 | #FA6C41 | 관광지 |

첨부한 PNG 원본은 assets에 보관했다. 지도 화면에서 색상을 입혀 표시하며 원본 파일은 변경하지 않았다. 기본 배경 #042A5D, 기본 글자 #FAFAFA, 포인트 #01A8AF·#FA6C41을 적용했다.

## 점수식을 이후 변경하는 방법

점수식 설명 PDF와 **그 시점의 최신 프로그램 파일 묶음**을 함께 제공하면 수정할 수 있다. 코드가 지금과 동일하다면 PDF와 변경 요구만 제공해도 된다. 이 웹사이트 자체에 PDF를 올려 점수식이 자동 변경되는 기능은 없다.

PDF에는 지표 정의, 거리/집계 반경, 점수 변환식, 정규화 기준과 방향, 가중치와 합계, 누락값·0개 처리, 관광 유형 수, 통계의 집계 방식·기준 월, 동점 순위를 명확하게 적는다. 설명되지 않은 값은 수정 전에 확인해야 한다.

실제 계산식은 report_model.py에 반영하고, 데이터 열이나 통계 집계가 바뀌면 report_io.py와 app.py도 수정한다. 알려진 입력·출력 예제로 계산 결과를 검증한 뒤 변경 파일을 GitHub에 교체하면 연결된 앱에 적용할 수 있다.

이번 수정은 기존 점수식과 750m 집계 반경·관광 유형 수 7개·최근 월 처리 방식을 유지했다.

## 검증

업로드 및 기존 계산식 테스트 12개가 통과했다. 합성 빈집 18개와 시설·통계 CSV 19개를 묶은 시험용 ZIP으로 자동 연결, 계산, 상세 지도 전환과 시설 아이콘 표시를 확인했다. 실제 708개 원자료와 배포 사이트 검증은 배포 후 수행한다.

설치된 Python 환경에서 `python -m unittest discover -p "test_*.py"`로 테스트하고, `python -m streamlit run app.py`로 실행한다. 기존 .venv를 사용한다면 먼저 app.py가 있는 폴더로 이동한 뒤 해당 환경의 Python으로 실행한다.
