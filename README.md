# 구해줘 빈집 — 확정 점수식 반영본 v5

사용자가 제공한 「부산_빈집_입지분석_변수와_가중치_정리.pdf」와 확인 답변에 따른 HYB 관광·부산 격자 p90 모델이다. PDF 관광형 각주와 달리 사용자가 표의 값을 확정 기본값으로 승인했다. 통계적으로 검증되었다는 의미는 아니다.

## 적용 방법

1. 기존 로컬 저장소를 별도 위치에 백업한다.
2. ZIP을 압축 해제한 뒤 폴더 안의 내용을 기존 app.py가 있는 폴더에 복사해 교체한다. .git과 .venv는 교체하지 않는다.
3. 신규 hyb_model.py, hyb_io.py와 변경된 app.py, report_model.py, diagnostics.py, upload_tools.py, visuals.py가 모두 필요하다. assets와 .streamlit/config.toml도 유지한다. app.py만 교체하면 안 된다.
4. 저장소 폴더에서 기존 가상환경으로 실행해 확인한다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

5. 확인 후 GitHub에 반영한다.

```powershell
cd C:\Users\winte\Desktop\binzip_data\rescue_abandoned_houses
git status
git add -A
git commit -m "Apply confirmed HYB scores and default weights"
git push
```

GitHub·배포 사이트에는 이 전달본을 자동으로 반영하지 않았다. push가 거절되면 강제 push하지 않고 원격 변경과 충돌을 확인한다.

## 확정 변수와 점수

모든 원지표는 0~1점이며 복수 지표 요인은 내부 단순평균이다. 최종 점수는 요인 가중합 × 100이다. 로그변환·표본 Min–Max·상수 요인 제외·누락값 0 채우기는 사용하지 않는다.

|요인|변수와 점수|
|---|---|
|R HYB 관광|1.5km 내 관광지 개수÷9와 등장횟수 appear_cnt 합계÷51의 평균. 각각 최대 1|
|Q 관광업종 매출밀도|빈집 행정동 sales_den÷103,284,830.17, 최대 1|
|T 교통|공영주차장 유무·도시철도 최근접 거리·750m 내 버스 개수÷51의 평균|
|S 안전|750m 내 CCTV 개수÷101·경찰시설 유무·소방시설 유무의 평균|
|F 생활편의|편의점·마트·약국 유무의 평균|
|J 산업접근|산업시설 최근접 거리|
|E 교육·보육|어린이집,유치원·초등학교 유무의 평균|
|U 대학접근|대학교 최근접 거리|
|D 기숙사 부족|3km 내 대학별 max(지원자 수 − 수용가능인원, 0)의 합÷661, 최대 1|

유무는 750m 이내 1, 없으면 0이다. 개수 점수는 최대 1이다. 거리 점수는 ≤750m:1 / ≤1,500m:0.75 / ≤2,250m:0.5 / ≤3,000m:0.25 / >3,000m:0이다. 정확히 3,000m는 0.25이다. 부산 격자 p90 기준값을 업로드한 빈집 표본에서 다시 계산하지 않는다.

|유형|요인 순서|기본 가중치|
|---|---|---|
|A 관광형|R,Q,T,S,F|0.5,0.1,0.1,0.2,0.1|
|B 근로자형|J,E,T,S,F|0.5,0.1,0.1,0.1,0.2|
|C 대학생형|U,D,T,S,F|0.3,0.2,0.2,0.1,0.2|

슬라이더는 유지했다. 각 값을 합계로 나누어 적용 가중치 합을 1로 맞춘다. 예: 70·10·10·20·10은 각 값을 120으로 나눈다. '확정 가중치로 초기화'는 위 기본값을 복원한다. 순위 변화 비교도 확정 기본값 기준이다.

## 입력 자료

CSV·XLSX를 각각 또는 ZIP으로 업로드한다. 파일명 및 열 자동 선택은 제안이므로 드롭다운을 확인한다. 빈집 ID·좌표·행정동은 연결용이며 별도 점수 변수는 아니다.

- 빈집: house_id, latitude, longitude, 행정동코드 또는 행정동명. 통계와 동일한 연결키를 사용한다. 주소에서 행정동을 추정하지 않는다.
- 관광지: 좌표·명칭·appear_cnt. 등장횟수는 실제 방문자 수를 의미하지 않는다. 관광유형 다양성은 사용하지 않는다.
- 매출: 행정동·sales_den. 월 열이 있으면 YYYYMM 중 최신 월만 반영한다. PDF 기준값과 같은 산정 방식·단위의 관광업종 매출밀도가 필요하다. 기존 매출액을 그대로 넣으면 안 된다. 업종별 원매출 여러 행을 자동 합산하여 밀도라고 간주하지 않는다.
- 대학/기숙사: 대학·캠퍼스별 한 행, 좌표, dorm_app(지원자 수), dorm_cap(수용가능인원). 두 열을 드롭다운으로 선택한다. **기존 unmet 열은 읽지 않는다.** 내부 unmet은 확정 식으로 새로 계산한 파생값이다. dorm_matched도 점수 변수로 읽지 않는다. 원자료의 미연결 상태를 0으로 채웠다면 업로드 전에 실제 결측으로 수정해야 한다.
- 기숙사 두 값 중 하나라도 누락되면 해당 대학을 3km 안에 둔 빈집은 D를 산정하지 않는다. 반경 내 대학이 실제 없으면 합계 0이다.
- 기숙사 자료는 대학 파일에 포함하거나 별도 좌표 파일로 연결한다. 별도 파일도 지역 대학 전체 목록과 누락값을 포함한다. 자료 없는 대학 행을 삭제하면 반경 내 대학이 없는 것으로 오인할 수 있다.
- 나머지 시설은 좌표·명칭·선택 ID를 사용한다. 경찰시설과 편의시설의 통합/분리 업로드는 유지했다.
- 방문인구·관광유형 수·도서관·운동시설은 확정 식에 없어 입력칸과 점수 계산에서 제외했다.

빈 시설 파일은 실제 시설 0개인지 누락 자료인지 확인해야 한다. 빈집을 701개로 임의 제한하지 않는다. 실제 업로드 개수와 모든 필수 변수의 유효값 여부를 표시한다. 동일 대학/캠퍼스 중복은 인원 중복 합산을 막기 위해 오류로 알린다.

examples는 헤더만 있는 입력 양식이며 실제 분석 데이터가 아니다. 실제 원자료·가상환경·Git 이력은 ZIP에 포함하지 않았다.

## 결과와 검증

유형별 상위 5위는 A:1위로 표시한다. 동점은 공동순위라 5개보다 많이 표시될 수 있다. 점 선택 시 해당 유형의 근거시설을 표시하며 확정 집계 범위를 따른다. CSV는 원지표·점수·요인·순위를, JSON은 파일 해시·열 연결·고정 기준·가중치·반경을 기록한다.

기숙사 예: 지원자 6,521 − 수용인원 4,205 → 2,316명. 기존 unmet=2,823은 사용하지 않는다.

test_report.py와 test_upload_tools.py로 점수 기준·거리 경계·결측·기숙사 식·표본 독립성·ZIP 및 분리 입력을 검증한다.
